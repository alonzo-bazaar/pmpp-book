* general procedure
a cl context is the big handle to everything
it is how we query for devices, how we access devices, everything
so the first thing we gotta do is create a context, for which we'll first need to create some context config data, and use that to get a context

next thing we do is find a gpu device using that context, and we create a command queue to that device

we'll use the command queue to issue shit like
"copy this cpu buffer into that gpu buffer"
"launch this kernel with these gpu variables"
"copy these gpu variables back into cpu ram"

* kernel code
opencl c is a subset of c99 with some add ons
that is to say, it's not really c but it's made to fool you into thinking you're writing c
I can't believe it's not C!

as far as we're concerned
prepend ~__kernel~ to a function signature to say the function in question is indeed a kernel (ie, will run on the device(gpu))

prepend ~__global~ to a kernel parameter to say the parameter in question will be allocated in global memory
global memory is a memory on the device visible to all threads that run therein
and that both the host and device can read from and write to 

every device thread/work item has an id
every work item dispatches on id to operate on this or that part of the data, you launch the kernel with a given amount of work items, each item does its own little thing, and once all the work items are done the entire work is done
